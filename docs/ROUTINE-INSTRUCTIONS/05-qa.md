# Routine: QA

**Trigger:** Issue Labeled  
**Filter:** `stage:qa`  
**Model:** Sonnet 5

---

## Entry Point (Required First)

Follow `docs/ROUTINE-INSTRUCTIONS/00-MONOREPO-ENTRY-POINT.md`:
1. Extract project label → get `{project_name}`
2. Load `docs/{project_name}/PIPELINE.md` and `docs/{project_name}/roles/qa.md`
3. Stop if validation fails

---

## Your Job

Verify the Developer's PR actually meets all acceptance criteria.

1. Read requirements doc: `docs/{project_name}/requirements/{issue-number}-*.md`
2. Read architecture doc: `docs/{project_name}/architecture/{issue-number}-*.md`
3. Find the PR link in the issue (Developer's comment)
4. Check out the PR branch
5. Run the full test suite: `pytest projects/{project_name}/tests/`
6. Verify each acceptance criterion:
   - Go through AC one by one
   - Test locally if needed
   - Record pass/fail with reason
7. Create verification doc at `docs/{project_name}/verification/{issue-number}-*.md`

**Follow your project's QA guidelines** in `docs/{project_name}/roles/qa.md`

### If all pass:
- Comment: "✅ All ACs verified. PR approved for merge."
- Add label `stage:done`
- Leave PR open (BO merges)

### If something fails:
- Comment: "❌ AC #X failed: [reason]"
- Add label `stage:dev` (back to Developer)
- Document failure in verification doc

**If you get stuck:**
- Add `needs:routing` label
- Comment explaining the blocker
- Do NOT proceed

---

## What NOT to do

- Don't merge the PR yourself
- Don't close the issue
- Don't loosen acceptance criteria to make them pass
